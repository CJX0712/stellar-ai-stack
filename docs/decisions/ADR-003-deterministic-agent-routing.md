# ADR-003 · 智能体确定性前置路由

- 状态：已采纳（2026-09-24）
- 作者：晨星

## 背景

小/本地模型在 ReAct 循环中对算术、日期类问题常输出错误答案或陷入无效循环，
且这类问题本不需要语言模型。若全交给 LLM，评估指标会被这类用例拉低且不可信。

## 决策

`Agent.run` 在进入 LLM 之前先做**确定性前置路由**：
- 含日期关键词（今天/日期/now/date…）→ 返回当前日期（本地 `datetime`）。
- 正则检出算术表达式（含 `+ - * /`、数字、一元负号，已归一化全角标点）→ 经安全 `ast` 求值后返回结果。
  - 仅允许 `BinOp / UnaryOp / Constant` 节点；`ZeroDivisionError` / `OverflowError` → ToolError。
- 其余问题才进入 ReAct：LLM 给 `Action(search/calculator/date)` → 执行 → 观察 → 合成 `Final Answer`。
- 循环受 `max_steps` 硬性上界约束。

## 后果

- 算术/日期 100% 正确且零延迟、零 LLM 调用。
- ReAct 仍真实存在（search → 合成），并保留工具扩展点。
- 评估中"设计上不检索"的用例从检索聚合剔除，指标不被污染。
- 代价：前置路由是正则启发式，复杂数学表达式（如带变量）不覆盖，交由 LLM。

## 备选

- 全部交给 LLM 的 ReAct：更"通用"但不可信、不可复现 → 否决。
- 用计算器工具让 LLM 自己决定：小模型常不调用或不信任结果 → 否决。
