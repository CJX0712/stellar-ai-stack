# ADR-001 · 模块化分层与接口注入架构

- 状态：已采纳（2026-09-24）
- 作者：晨星

## 背景

目标是一套"世界级、端到端可实际运行"的 AI 系统，要可独立验证、可复现、可扩展。
若把所有逻辑塞进一个脚本，无法逐模块单测，也无法在不启动整系统的情况下验证某一环。

## 决策

采用 **分层 + Protocol 注入** 架构：
- 所有对外端口在 `core/interfaces.py` 中定义为 `Protocol`。
- 模块只依赖接口，运行时由 `composition.build_system` 注入实现。
- 唯一装配点是 `composition`，入口（api / cli）只装配、零业务。

## 后果

- 每个模块可独立单测，可用 fake 实现替换 LLM / 向量库 / 嵌入。
- 新增后端（Qdrant、Mongo、远端嵌入）只需新增一个满足 Protocol 的类 + 一个分支。
- 代价：多一层抽象与装配代码；对本项目规模利远大于弊。

## 备选

- 单体脚本：更快写，但不可独立验证、不可复现 → 否决。
- 重型框架（LangChain 全量）：功能多但黑箱、依赖重、难验证 → 否决，改为复用其范式而非其代码。
